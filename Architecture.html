1 · What it is

The product is one static page with three user-facing views: the marketing/import state, the financial dashboard with recommendations and seven independent agents, and the savings directory. A settings drawer edits budgets, rules, categories, backups and manual entries without leaving the page.

inputFinancial exportsBank and card files are parsed in memory. Old BIFF8 workbooks, modern SpreadsheetML workbooks and CSV files share one normalized workbook shape.
analysisHousehold modelTransactions are deduplicated, categorized, grouped by month and converted into budgets, recurring charges, alerts and forecasts.
agentsSeven independent checksLearning, anomaly, missing-charge, duplicate, subscription, budget and payday engines derive typed findings from the same normalized state.
experienceOne decision number firstA safe-to-spend guide turns the payday agent into a weekly and daily allowance, with an expandable calculation before the detailed dashboard. No account or remote database is required.
guidanceSavings directoryOfficial comparison services and direct links to pension, provident, training-fund and portfolio-management companies live in a separate view.

5 · Render

The application updates semantic HTML, tables and SVG charts using locale-aware date and ILS formatters.

Ordering and consent rule. A manual category assignment always wins. Automatic rules are ordered and first-match-wins. The learning agent may propose a rule and the budget agent may propose a ceiling, but neither mutates state before explicit approval. Neutral transfers remain visible but do not inflate household income or spending totals.

5 · State and persistence

The application keeps one serializable AppState. Derived charts, summaries and agent findings are recalculated rather than stored, which avoids synchronization bugs when transactions, locale, budget or category changes. Only an approved learned rule or approved budget ceiling joins persisted state.

tx
Normalized transactions, including source, pending state and stable identity.
overrides
Transaction ID → category ID. This is the highest-precedence categorization layer.
rules
Ordered text-match rules used for repeatable categorization.
cats
User-editable category definitions and financial kind: expense, income or neutral.
budgets
Category ID → monthly ILS ceiling.
accounts
Account labels detected in imported reports.
month
Current view selection; reset safely when persisted state loads.
automaticBrowser persistenceState is serialized to mazan-habait/v1. A blocked or corrupted store falls back to a clean in-memory session.
portableBackup fileExport and import provide an explicit user-controlled path between browsers or computers.

Optional cloud data model

identityuser_profilesOnly user ID and preferred locale; no financial payload.

consentconsent_acceptancesPurpose, statement version, locale and server timestamps for acceptance or withdrawal.
Not persisted. Agent findings, forecasts, JWTs, typed names, signatures, IP addresses and device fingerprints are excluded. Derived values are recalculated after restore.

6 · Localization architecture

he.json is the canonical key set. English, Amharic and French must expose the same keys and the same named parameters, while remaining free to reorder parameters inside a sentence.

// Resource
"recommendationsSummary":
  "{count} recommended actions for {account}, based on {month}."

// Runtime
t('recommendationsSummary', {
  count: recommendations.length,
  account: accountLabel,
  month: monthLabel(selectedMonth)
})
documentDirection and languagelang, dir and the application containers update together. Hebrew is RTL; English, Amharic and French are LTR.
formattingOne financial currencyDates and number punctuation follow the locale, while monetary values remain ILS in every language.
accessibilityAttributes are localized tooText, placeholders and accessible labels use separate data attributes backed by the same resource contract.

7 · Privacy and trust boundary

  • Selected reports are read by browser APIs and parsed in memory.
  • All seven financial agents are deterministic local functions; there is no remote model call.
  • Local use sends no transaction to a server. Future cloud backup is separate and requires sign-in plus explicit, versioned consent.
  • The API accepts only a publishable key, verifies the JWT with Supabase Auth and relies on grants plus owner-only RLS; no service-role key is present.
  • Local Prometheus metrics contain availability, latency, method and status only; JWTs and financial payloads are excluded.
  • Agent findings are indicators, not financial advice and require human verification.
  • Consent may be declined or withdrawn without disabling local use; acknowledgement is not a waiver of non-waivable rights.
  • Marketing attribution records campaign parameters and local events, never bank report contents.
  • External directory links use noopener noreferrer and open only after an explicit action.
Failure mode. If local storage is unavailable, the app warns the user and keeps working in memory until the tab closes. A storage failure does not redirect data elsewhere.

8 · Testing strategy

The suite is layered by speed. Cheap structural failures surface before a browser is launched; end-to-end and accessibility checks cover the composed product last. The Docker runner merges Vitest and Playwright events into a static Allure report served on localhost.

9 · Extension points

new localeExtend the locale contractAdd the locale configuration and a complete resource file. Parameter-parity tests make sentence drift visible immediately.
new institutionAdd an adapterRecognize its header vocabulary and map it to the normalized transaction shape; keep institution-specific rules outside rendering.
new agentDerive, explain, approveAdd a pure typed engine to financial-agents.ts, a localized plain-language card, stable test IDs and independent unit/API/component/browser coverage. Any mutation requires an explicit approval action.
future splitReduce the composition rootapp.ts deliberately owns orchestration today. As the product grows, workbook reading, forecast calculation and DOM views are the clearest extraction seams.
Architecture guardrail. Do not enable cloud upload until authentication, server-side consent recording, deletion and recovery journeys, controller contact details, retention policy, threat model and legal review are complete. Local use must remain available after refusal.
