# מאזן הבית

יישום דפדפן פרטי לניתוח דוחות בנק וכרטיסי אשראי, מעקב אחר תקציב, תחזית תזרים והמלצות פעולה. הקבצים נקראים מקומית בדפדפן ואינם נשלחים לשרת.

## יכולות עיקריות

- ייבוא קובצי XLS,‏ XLSX ו־CSV של בנקים וכרטיסי אשראי.
- תמונת מצב חודשית, קטגוריות, תקרות תקציב וחיובים חוזרים.
- תחזית תזרים והמלצות פעולה לפי הנתונים שיובאו.
- מסך קישורים לכלים רשמיים ולחברות המנהלות פנסיה, גמל, קרנות השתלמות ותיקי השקעות.
- ממשק מלא בעברית, אנגלית, אמהרית וצרפתית, כולל מעבר RTL/LTR.
- גיבוי ושחזור של הנתונים המקומיים.

## הפעלה מקומית

נדרשים Node.js ו־npm.

```bash
npm install
npm run build
```

להרצת האתר דרך שרת מקומי:

```bash
ruby -run -ehttpd . -p 8765
```

לאחר מכן פותחים את `http://127.0.0.1:8765/mazan-habait.html`.

## תרגום מבוסס מפתחות

קובצי השפה נמצאים בתיקייה `resources/`:

- `he.json` — עברית, שפת המקור.
- `en.json` — אנגלית.
- `am.json` — אמהרית.
- `fr.json` — צרפתית.

טקסט סטטי מחובר למפתח באמצעות `data-i18n`. אפשר לתרגם גם `placeholder` ו־`aria-label` באמצעות `data-i18n-placeholder` ו־`data-i18n-aria-label`.

משפטים דינמיים משתמשים בפרמטרים בעלי שם, כך שכל שפה יכולה לבחור סדר מילים טבעי:

```json
{
  "amountAsOfDate": "{amount} נכון ל־{date}"
}
```

```ts
t('amountAsOfDate', { amount: '₪1,250', date: '23.08.2026' });
```

בעת הוספת מפתח יש להוסיף אותו לכל ארבעת קובצי השפה ולשמור על אותם שמות פרמטרים. בדיקות החוזה מאמתות זאת אוטומטית.

## בדיקות

הבדיקות מסודרות לפי עלות הרצה: יחידה, API וחוזה רצות תחילה; בדיקות רכיבים משתמשות ב־JSDOM; בדיקות דפדפן ונגישות רצות בסוף עם Playwright.

```bash
npm test                 # יחידה, API, חוזה ורכיבים
npm run test:e2e         # תרחישי דפדפן, שפות ונגישות
npm run test:e2e:report  # פתיחת דוח ה־HTML האחרון
npm run test:all         # כל הבדיקות
```

בדיקות הנגישות משתמשות ב־axe ובודקות כללי WCAG 2 ברמות A ו־AA במצב הריק, בלוח עם נתונים, במגירת ההגדרות ובמסך החיסכון וההשקעות. מטריצת Playwright מריצה את התרחישים ב־Desktop Chrome, בפרופיל Android של Pixel 7 וב־WebKit עם פרופיל iPhone 13. בדיקות המובייל הייעודיות מאמתות יעדי מגע, safe areas, מניעת auto-zoom בשדות, overflow ואת מסע הייבוא המלא. האמולציה מספקת כיסוי regression עקבי, אך אינה תחליף לבדיקה ידנית על מכשיר פיזי עם VoiceOver ו־TalkBack לפני פרסום מהותי.

בדיקות ה־E2E משתמשות ב־Page Object Model. המחלקה `BasePage` מרכזת ניווט, איפוס מצב, viewport ובדיקות overflow; העמודים `HomePage` ו־`ArchitecturePage` מרכיבים רכיבי משנה ייעודיים לשפה, העלאות, שיווק, דשבורד, הגדרות וספריית החיסכון. כל העמודים ורכיבי המשנה מאותחלים כ־fixtures טיפוסיים בקובץ `tests/e2e/fixtures.ts`; ה־fixture של `HomePage` מקבל את רכיביו בהזרקה, והבדיקות אינן יוצרות Page Objects בעצמן. פעולות Page Object מסומנות ב־`@step('Simple action description')`; ה־decorator עוטף אותן ב־`test.step`, כך שהדוח מתעד פעולות משתמש בשפה פשוטה במקום שמות מחלקות ומתודות. דוח ה־HTML המובנה נוצר כברירת מחדל בתיקייה `playwright-report/`.

## פריסה אוטומטית ל־Vercel

ה־workflow בקובץ `.github/workflows/ci.yml` מריץ build ואת כל הבדיקות בכל push ו־pull request. פריסת production מתבצעת רק לאחר הצלחה מלאה, ורק ב־push לענף `main` או בהפעלה ידנית באמצעות `workflow_dispatch`. ריצת schedule בודקת את המוצר אך אינה פורסת.

יש להגדיר ב־GitHub Actions את ה־secrets הבאים:

- `VERCEL_TOKEN` — טוקן CI ייעודי מחשבון Vercel.
- `VERCEL_ORG_ID` — מזהה החשבון או הצוות ב־Vercel.
- `VERCEL_PROJECT_ID` — מזהה הפרויקט `home-economy-stabilation`.

אין לשמור את הערכים עצמם בקוד או בקובצי environment שנכנסים ל־repository.

```text

tests/e2e/page-objects/ עמודי בסיס ורכיבי Page Object לבדיקות הדפדפן
tests/                  בדיקות יחידה, חוזה, רכיבים ו־E2E
```

## פרטיות והבהרה פיננסית

היישום נועד להצגת מידע ולסיוע בהתארגנות בלבד ואינו ייעוץ פנסיוני, השקעות או מס. רשימת החברות אינה דירוג או המלצה; יש להשוות תשואות, דמי ניהול, סיכון ושירות בכלים הרשמיים ולשקול ייעוץ מבעל רישיון.
